# План: Какие субагенты можно подключить под проект kod

> Проект: **Код бессмертия** (Laravel 13 + React 19 SPA, Docker, PostgreSQL)
> Режим: Plan mode (только планирование, без исполнения)
> Дата: 2026-06-29

---

## 1. Краткая классификация

Все субагенты можно разделить на 4 уровня интеграции с проектом `kod`:

| Уровень | Тип | Назначение | Сложность |
|---------|-----|-----------|-----------|
| **A** | Встроенные субагенты Hermes (`delegate_task`) | Параллельные подзадачи в рамках сессии | Просто |
| **B** | Внешние AI-кодинг агенты (Claude Code, Codex, OpenCode) | Автономная разработка, рефакторинг, фичи | Средне |
| **C** | MCP-серверы | Подключение специализированных инструментов (поиск, ФС, GitHub, БД) | Средне |
| **D** | Планировщики и фоновые процессы (cron, spawn, kanban workers) | CI/мониторинг/долгие задачи | Средне |

---

## 2. Уровень A — Встроенные субагенты Hermes (`delegate_task`)

Уже доступны прямо сейчас, без настройки.

**Механизм:** `delegate_task(goal, context, toolsets)` — порождает изолированного субагента в том же процессе. До 3 параллельных. Результат возвращается в виде summary.

### Что можно делегировать для kod:

| Сценарий | Пример промпта | toolsets |
|----------|---------------|----------|
| **Параллельное тестирование** | Запустить PHPUnit и проверить, какие тесты падают | `[terminal]` |
| **Рефакторинг одного компонента** | «Переписать AnketEditorPage на React Hook Form + Zod — все стейты, валидацию, отправку» | `[terminal, file, search]` |
| **Код-ревью PR** | «Проверить последние изменения в PR-ветке на security-дыры, утечки токенов, необработанные исключения» | `[terminal, web]` |
| **Синтаксический анализ CSS** | «Найти дублирующиеся медиа-блоки, конфликтующие !important, неиспользуемые классы в app.css» | `[file, search]` |
| **Извлечение данных из .docx/PDF** | «Извлечь контент из tariff.docx и структурировать в JSON» | `[terminal, file]` |
| **Проверка зависимостей** | «Проверить composer.json на известные CVE через npm audit / composer audit» | `[terminal, web]` |
| **Генерация тестов** | «Написать PHPUnit-тесты для ImageService, покрыть cover() и save()» | `[file, terminal]` |
| **Миграция .docx → React-страницы** | «Из variants_qr.docx сделать 6 карточек с иконками и описанием в React» | `[file, terminal]` |

**Плюсы:** уже работает, ноль конфигурации, изолированный контекст.
**Минусы:** не переживает прерывание сессии, лимит 3 параллельных.

## 3. Уровень B — Внешние AI-кодинг агенты

Для автономной длительной работы — рефакторинг, написание фич, анализ кода.

### Варианты:

| Агент | Установка | Плюсы | Минусы |
|-------|-----------|-------|--------|
| **Claude Code** (Anthropic) | `npm i -g @anthropic-ai/claude-code` | Лучшая кодогенерация, TUI, `/review`, `/plan`, context management | Нужен API-ключ Anthropic, дорогой |
| **Codex CLI** (OpenAI) | `npm i -g @openai/codex` | Простой, `exec` one-shot без PTY | Не такой глубокий контекст |
| **OpenCode** (провайдеро-нейтральный) | `npm i -g opencode-ai` | Любой провайдер, открытый исходник | Меньше фич |

### Что можно делегировать (от уровня B):

- **Автономная разработка фичи**: «Реализовать страницу /news с админкой — миграция, модель, контроллер, роуты, React-компонент, тесты»
- **Массовый рефакторинг**: «Заменить все инлайн-стили на Tailwind-классы в MemorialPage»
- **Миграция данных**: «Написать artisan-команду для импорта всех пользователей из WordPress-БД в Laravel»
- **Комплексный рефакторинг CSS**: «Убрать все дубликаты, !important, конфликтующие селекторы в app.css, разбить на модули»

### Способ запуска:

```bash
# One-shot через print mode (без PTY)
claude -p '...' --allowedTools 'Read,Edit,Write,Bash' --max-turns 20

# Фоновый процесс через tmux
tmux new-session -d -s kod-agent -x 140 -y 40 'codex exec "..."'
```

**Плюсы:** полностью автономные, переживают закрытие CLI, могут работать часами.
**Минусы:** нужно ставить + настраивать аутентификацию, расход API-кредитов.

## 4. Уровень C — MCP-серверы

Подключаются через встроенный MCP-клиент Hermes. Инструменты MCP-сервера становятся доступны как нативные хермесовские тулы.

### Уже интересуетесь (из памяти):

> **Tavily MCP** — поиск (1000 запросов/мес бесплатно). Нужен API-ключ, когда появится.

### Полезные MCP-серверы для kod:

| MCP-сервер | Команда | Для чего в kod |
|-----------|---------|----------------|
| **Tavily Search** | `npx -y @tavily/mcp` | AI-поиск документации, гайдов, решений |
| **GitHub** | `npx -y @modelcontextprotocol/server-github` | Работа с issues, PR, code review без gh CLI |
| **Filesystem** | `npx -y @modelcontextprotocol/server-filesystem /var/www` | Чтение/запись файлов вне проекта |
| **PostgreSQL** | `uvx mcp-server-postgresql` | Прямые SQL-запросы, анализ данных |
| **Puppeteer/Browser** | `npx -y @modelcontextprotocol/server-puppeteer` | E2E-тестирование страниц |
| **Sentry** | `npx -y @1zicha/mcp-sentry` | Мониторинг ошибок |
| **Memory/Knowledge** | `npx -y @modelcontextprotocol/server-memory` | Хранение документации проекта |
| **SQLite** | `uvx mcp-server-sqlite` | Локальная БД для вспомогательных данных |

### Пример конфигурации (`~/.hermes/config.yaml`):

```yaml
mcp_servers:
  tavily:
    command: "npx"
    args: ["-y", "@tavily/mcp"]
    env:
      TAVILY_API_KEY: "tvly-..."
  github:
    command: "npx"
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_PERSONAL_ACCESS_TOKEN: "ghp_..."
```

После настройки MCP-инструменты появляются как `mcp_tavily_search`, `mcp_github_list_issues` и т.д.

**Плюсы:** лёгкая интеграция, без кода, инструменты доступны во всех сессиях.
**Минусы:** нужен RESTART Hermes после изменений, некоторые MCP-серверы требуют API-ключи.

## 5. Уровень D — Планировщики и фоновые процессы

### D1. Cron-задачи Hermes

Уже есть одна (`Kod DB Backup` в 3:00). Можно добавить:

| Задача | Расписание | Описание |
|--------|-----------|----------|
| **Бэкап БД** | ✅ 3:00 ежедневно | Уже настроен |
| **Health-check приложения** | Каждые 10 мин | Проверка, что /api/health отвечает 200 |
| **Мониторинг логов** | Каждые 30 мин | `grep ERROR storage/logs/*.log` — уведомление в Telegram |
| **Проверка SSL** | Раз в день | Проверка срока действия сертификата |
| **Проверка обновлений** | Раз в день | `composer outdated` + `npm outdated` |
| **Анализ ошибок** | Раз в час | Анализ логов и выдача рекомендаций |

### D2. Spawn независимого Hermes

Запустить отдельный процесс Hermes (через `hermes chat -q` или tmux) для независимой работы:

- **Hermes-монитор** — постоянно висит, следит за логами
- **Hermes-тестировщик** — каждые N минут запускает тесты и шлёт результат
- **Hermes-ресечер** — ищет лучшие практики по Laravel 13 / React 19, сохраняет в Obsidian

### D3. Kanban-воркеры (multi-agent workflow)

Если задач становится много — система kanban с очередью:

1. Hermes-координатор формирует задачи в доску
2. Несколько профилей/воркеров забирают задачи из очереди
3. Каждый воркер работает изолированно
4. Результаты сводятся в доску

Для kod это имеет смысл, когда начнётся параллельная работа над:
- Бэкенд (новые API-эндпоинты)
- Фронтенд (новые страницы)
- Тестирование
- Документация

## 7. Рекомендуемый порядок подключения

### Этап 1 — Быстрая победа (сегодня)

1. Настроить **Tavily MCP** — у вас есть интерес и бесплатный лимит 1000 запросов/мес
2. Добавить 2-3 cron-задачи: health-check, мониторинг логов

### Этап 2 — Усиление разработки (эта неделя)

3. Установить **Claude Code** или **Codex CLI** для автономного рефакторинга
4. Настроить **GitHub MCP** для работы с PR/issues через агента

### Этап 3 — Полная автоматизация (по мере необходимости)

5. Настроить **Kanban-доску** для multi-agent разработки
6. Запустить **Hermes-монитор** как фоновый процесс
7. Подключить **MCP-базы данных** (PostgreSQL) для прямых SQL-запросов
